# Album Art and Playlist Colour Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Albums get a thumbnail from the embedded cover of the first file that has one; songs show their album's picture; a playlist's tile colour can be chosen.

**Architecture:** The server reads the embedded picture at upload, makes a small JPEG (`ConfigArt.ThumbnailMaxPixels`, SkiaSharp) and keeps it as a file per album next to the media files; `EntityAlbum.TimeArtModified` says when it changed. `GET /Album/{id}/Art` serves it with an ETag. A device fetches it with its token, keeps a copy, and shows it through an `AlbumArt` component. `EntityPlaylist.ArtHue` is a nullable chosen hue.

**Tech Stack:** .NET 10, EF Core (SQLite), SkiaSharp, TagLibSharp, Mediator, SignalR, MAUI Blazor Hybrid, Fluxor, xUnit v3.

**Spec:** `docs/specs/2026-11-24-cover-art-design.md`

## Global Constraints

- Thumbnail: JPEG, at most `ConfigArt.ThumbnailMaxPixels` on the longest side (32 to 2048, default 300, section `Art` in `appsettings.json`), quality 80 as a constant, never enlarged.
- A picture is only ever put into an album that has none (`TimeArtModified is null`); it never replaces one. A failed picture step never fails an upload.
- Playlist hue: 0 to 359, null means the hue made from the ID.
- "Media" in code, "song" in user-facing text. One class per file; enums end in `Enum` in an `Enums` folder; no magic strings; DI names kind first; `is null`, no `!`; no inline logic in Razor attributes; sizes and colours as CSS variables, no size literals in component CSS (a project test fails on them).
- Run only relevant tests: `cd Noxy.NET.Test/Noxy.NET.Test.UnitTest && dotnet build && ./bin/Debug/net10.0/Noxy.NET.Test.UnitTest.exe -class "<ns.Class>"`; integration tests the same from `Noxy.NET.Test.IntegrationTest` (never the whole integration suite at once: it can hang). `dotnet test` does not work. Build the App with `--no-dependencies` and read only ` error CS` / ` error RZ` lines.
- The migration needs the EF tool, which needs the API **stopped**: ask the user before Task 4, and stop there until they say it is.
- Do not commit production code: stage new files by name; the user commits. Test files alone may be committed.

## Review Focus

- An upload whose file has no picture, a corrupt picture, or a huge one (decode fails, or is slow) still succeeds; the album just has no picture.
- A second upload of the same album with a picture fills an album that has none, and never replaces one it has.
- Two uploads of the same new album at once: one picture is kept and nothing throws.
- Deleting or merging an album removes its picture file; the picture of another user's album is never served (404).
- A device with an old copy shows the new picture after `AlbumUpdated`, and never shows a broken-image icon (null means the default tile).
- Changing `ThumbnailMaxPixels` leaves pictures already kept alone.
- Playlist `artHue` outside 0 to 359 is refused; `null` clears it; an edit that leaves it out does not touch it.
